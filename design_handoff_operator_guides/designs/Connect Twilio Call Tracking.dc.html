Connect Twilio call tracking

Route calls for numbers running on Twilio (including WizCaller-managed numbers) into the dashboard.

5 steps Signed, no URL secret

Why this matters

This serves the same purpose as CallRail, for numbers running on Twilio — including numbers managed through WizCaller, since those are Twilio numbers underneath. Once set up, Twilio calls route to the right property in the dashboard automatically, matched by the dialed number.

Twilio path vs CallRail path
Twilio status callback → X-Twilio-Signature verified with TWILIO_AUTH_TOKEN no secret in URL
CallRail webhook → ?secret= in the URL
→ Matched on the dialed number, same as CallRail.

Before you start

Have on hand:

Pre-flight
The property's Twilio number
Access to the Twilio console (and to WizCaller, if the number is managed there)
The Twilio Auth Token for the account (Twilio console → Account Dashboard)

4
Deploy

Set TWILIO_AUTH_TOKEN, then redeploy

Set the Twilio Auth Token in the dashboard environment (Vercel → Project → Settings → Environment Variables) as TWILIO_AUTH_TOKEN. The dashboard uses it to verify Twilio's X-Twilio-Signature on every inbound call — this is proper request signing, so there is no secret in the URL.

How to check it worked

Place a test call of at least 20 seconds to the number. Within a minute, in the dashboard open Settings → Webhooks and confirm an event appears with auth valid — and that the call shows on the property's page with the red Twilio badge.

WARNING Very short calls (under ~10 seconds) may not complete a status callback. Always test with a call of 20+ seconds.
